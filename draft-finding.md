# Draft finding (for review; not posted)

Tested Graph-then-EXO on PowerShell 7.6.6 with Microsoft.Graph.Authentication 2.40.0 and ExchangeOnlineManagement 3.10.1, one fresh process per scenario. Importing Graph without connecting does not break EXO; a Graph WAM sign-in first does. Managed resolution is not the fault: each module ends up with its own MSAL 4.83.1 stack (Graph in msgraph-load-context, EXO in Default), and Graph's AssemblyResolve handler answered none of EXO's requests. The break is native. NativeInterop's P/Invokes bind by the bare name msalruntime, so EXO's wrapper reaches the msalruntime.dll Graph loaded first, and startup fails with ApiContractViolation "Authenticator Factory has already been started". RuntimeBroker swallows that into a null Core and its constructor NREs. #3789 isolates managed code only, so expect this direction to survive it; -DisableWAM avoids it.
